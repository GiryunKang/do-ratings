검토일: 2026-09-12. 범위: 홈, 탐색, 대상 상세, 평가 작성, 공통 내비게이션, 기존 미션·예측. 코드를 읽고 실제 서비스의 기존 1440×4070 홈 스크린샷을 확인했다. 아래 행 번호는 작업 시작 당시 소스 기준이다. 출시 승인 문서가 아니며 실제 검증 결과와 남은 제한을 분리한다.

## 핵심 판단

제품에는 이미 탐색·리뷰·미션·예측·배틀·스트릭 기능이 충분하다. 지금 필요한 것은 평가할 대상을 찾고, 경험을 작성하고, 저장 결과를 확인하는 경로의 일관성이다. 브랜드의 주황색과 청록색을 유지하면서 검색·평가 행동을 우선하고, 게임 재미는 점수 방향을 유도하지 않는 탐험과 실제 기록에 연결한다.

기준 이미지: `C:/Users/USER/Documents/Projects/docs/do-ratings-check-20260912/home-desktop.png`. 화면에서 첫 평가 카드보다 커버 평점·Live Index·이동 리본·TOP5가 먼저 나타나며, 동일 주제가 반복된다. 1건 평가의 10.0 점수가 매우 크게 나타나고 같은 대상이 하단에는 5.0으로 표시된다. 주목할 대상 이미지에는 깨진 이미지가 보인다.

## 구현 계약

### Home

- 첫 화면 제목은 사용자의 경험과 행동을 설명한다. 예: “경험을 점수로 남겨보세요”. 검색 라벨과 검색 버튼은 실제 동작해야 한다.
- 주 행동은 “평가할 대상 찾기”. 1개 주제의 평균 숫자를 대형 hero로 쓰지 않는다.
- 경험 기반 제안은 “최근 다녀온 곳”, “이용해 본 서비스”처럼 긍정/부정 점수를 미리 결정하지 않는 문장으로 쓴다.
- 카테고리는 기존 route를 유지하며 실제 대상 수를 표시할 때만 집계 수를 사용한다.
- 평점 표본이 적어도 숨기지 않는다. `8.0 / 10 · 평가 1개`로 함께 읽히게 한다. 평가 0건인 대상을 평점 순위에 섞지 않는다.
- 탐험은 하나의 명확한 모듈로 연결한다. 완료 진행도는 계정의 실제 저장된 리뷰에서 계산한다. 새로고침·계정전환·수정·삭제 시 달라질 수 있는 기록임을 정확하게 처리한다.
- 최근 리뷰가 없으면 낮은 높이의 정직한 안내와 첫 평가 행동을 제공한다. 여러 빈 카드와 무기한 skeleton을 반복하지 않는다.

### Shell

- desktop: 좌측 내비를 유지하되 홈/탐색/랭킹/탐험/내기록이 주요 항목이다. 관리자는 권한 사용자에게만 노출한다.
- 320·375·414·768px: 한 화면의 한 주요 과업에 집중. 768px에서 폭 256px 사이드바가 콘텐츠를 압박하면 넓은 화면에서만 펼친다.
- 헤더 검색 아이콘은 접근 가능한 이름을 갖는다. current page는 aria-current로 표시한다.
- 하단 내비 5항목을 유지하되 선택 상태는 색상 외에도 형태/문구로 드러낸다. safe-area와 sticky 요소 겹침을 검증한다.
- 최소 44px 클릭 영역, 본문 16px를 기본으로 사용하고 부연 정보는 12px보다 작게 만들지 않는다. primary는 실제 다음 행동에만 사용한다.
- 기존 디자인 토큰을 사용하고 테마 별 색상·focus·reduced motion을 공통 규칙으로 처리한다.

### Review

- 작성 페이지는 대상 이름→평점→제목→본문→기존 작성 안내→저장 순서다. 현재 서버의 5점 저장 계약은 변경하지 않는다.
- 별 선택은 44px이며 키보드 방향키로 0.5별=1점, Home/End로 양 끝값을 선택한다. 보이는 값은 `7.0 / 10`이다. 숫자는 별과 별도 행으로 배치한다.
- 익명 사용자의 초안은 subject+탭 익명ID namespace에 저장한다. 명시적 로그인 흐름에서 한번만 계정 namespace로 이전한다. 사용자 A의 초안은 B에서 읽지 않는다. 서버에 이미 리뷰가 있으면 서버 내용을 우선한다.
- 초안은 저장 불가/만료/JSON 손상을 견딘다. 로그인 및 회원가입의 redirect는 locale를 포함하는 검증된 앱 경로만 허용한다. 외부 주소·역슬래시·경로 탈출은 거부한다.
- 저장 전 validation, profanity, 동의, 로그인 검증은 유지한다. 제출중 모든 입력과 중복제출을 잠근다. 오류는 role=alert로 알리고 작성 내용을 보존한다.
- 새 리뷰의 sub_ratings에는 사용자가 선택한 `overall`만 기록해 기존 평균 trigger와 호환한다. 이미 세부평가가 있는 편집은 해당 JSON을 유지한다. 종합점수만 바뀐다는 점을 안내한다.
- 응답의 id와 저장 점수가 확인된 뒤에만 성공 화면과 `ratings:review-saved` 이벤트를 실행한다. 실제 서버 점수가 다르면 “저장된 점수 확인이 필요해요”와 기존 리뷰 링크를 제공하고 재제출을 유도하지 않는다.
- 성공 화면은 유지된다. “저장한 리뷰 보기”와 “내 탐험 기록”이 다음 행동이다. 자동 페이지 이동·전면 폭죽·순번 과장·가짜 XP를 사용하지 않는다.

## 이번 담당 구현과 검증

변경 파일: `ReviewForm.tsx`, `StarRating.tsx`, `QuickRateStars.tsx`, 작성 page, auth login/signup/callback, 공통 `AuthForm.tsx`, `draft.ts`, `return-to.ts`, `review-save.ts`. 기존 이미지 DB는 수정하지 않는다. 기존 폼의 업로드 state에는 실제 입력 UI/setter가 없어 실행되지 않았으며 새 폼에서 사용 불가능한 경로를 제거했다.

1차 실행 결과: `npx.cmd tsc --noEmit` 통과, 담당 TSX/util ESLint 통과, `node --experimental-strip-types --test src/lib/utils/review-flow.test.mjs` 7개 통과. 여기에는 경로 보안·초안 계정 격리·기존 리뷰 우선·만료/손상 저장소·서버 점수 불일치가 포함된다. 브라우저 결과는 `review-browser-check.json`과 review/login/signup PNG에 별도 기록하며, 해당 파일이 없는 동안 UI 통과로 해석하지 않는다.

남은 위험: OAuth 제공자의 callback allowlist, 이메일 확인이 새 탭에서 열릴 때 원래 탭으로 돌아오는 동선, 운영 DB trigger 최신 상태, 실제 인증된 저장→목록 반영은 운영 mutation 없이 완전히 검증할 수 없다. 기존 테스트 파일에 자격증명 하드코딩이 발견되어 해당 스크립트를 실행하거나 재사용하지 않았다. 인증정보 값은 이 문서에 기록하지 않는다.
